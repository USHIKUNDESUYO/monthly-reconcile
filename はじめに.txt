1 初回の確認と保存・再開
========================

最初の1組を確認し、保存した記録を開き直す

初めて使う場合は、同梱の架空データで1組を確認します。JSONとCSVを保存し、別のタブでJSONを開き直すところまで試してください。1組の確認は操作の練習で、全件の照合完了とは異なります。

画面を開いて架空データを入れる

月次照合の案内同梱版（https://github.com/USHIKUNDESUYO/monthly-reconcile/releases/tag/v0.1.0-preview.20261014-guides.1）のZIPを保存し、右クリックして「すべて展開」を選びます。展開したフォルダーのmonthly-reconcile.htmlをChromeまたはEdgeで開いてください。サーバーや追加アプリの導入は不要です。

「架空データで試す」を押すと、2026年9月の帳簿100行と請求100行を比較します。入力は200行、照合候補は80組です。残る行も画面の一覧へ表示されます。確認者IDにはA01など、自分で決めた識別用の文字を入力してください。氏名は不要です。

判断と理由を記録する

「2 未記入の候補を1組確認する」を押すと、帳簿と請求の元データが並びます。両側の日付・相手先・金額と元の行を見てください。

判断欄で「この候補を採用する」を選ぶ場合は、理由欄にも確認した根拠を入力します。この架空の練習なら、実際に一致を確認した上で「両側の日付・相手先・金額と元の行を確認した」と記入できます。続けて「候補の両側の日付・相手先・金額と元行を確認した」にチェックし、「この判断を記録する」を押します。

判断を決められない場合は「未解決」を選び、足りない資料や確認したい点を理由に残します。採用用のチェックは不要です。「記録せずに閉じる」では判断は記録されません。候補があるだけでは、利用者の確認が済んだ状態になりません。

最初の1組を採用すると、両側の2行に判断が記録されます。画面では「記入 2行」「未記入・未解決 198行」を確認できます。200行すべてが完了した意味ではありません。

2つのファイルを保存し、別のタブで再開する

「① JSONを保存（再開用）」と「② CSVを保存（確認表）」を押します。ダウンロード先で2つのファイルがあることを確認してください。CSVは確認表、JSONは入力と判断記録を含む再開用ファイルです。

元の画面を残し、同じmonthly-reconcile.htmlを別のタブで開きます。「保存した記録を再開する」を開き、中の「再開するJSON」から、今保存したJSONを選んでください。読み込みが終わったら、対象月が2026年9月、記入が2行、未記入・未解決が198行であることを確かめます。

確認者IDの入力欄は再開時には空欄になります。A01などを入力し、全行の一覧にある記録済みの行の「確認」を押して、判断・理由が戻っていることを確認してください。読み終えたら「記録せずに閉じる」を押します。IDの入力やこの閉じ方では、保存した判断を書き換えません。IDは行を開くときにも必要です。

元の入力CSVや確認表CSVでは、判断記録を再開できません。開き直せないときは元の画面を残し、再開用JSONを選んだか、ファイルが4MB以内かを確認します。JSONを手で書き換えず、元の画面から保存し直してください。

自分の資料へ進むとき

対象月と金額の基準を両側でそろえます。実データのJSONには入力も含まれるため、組織の保存先と共有設定を確認してください。入力の列・件数・金額形式はREADME（README.md#自分のcsvを使う）に記載しています。

今回の練習は架空データによる操作確認です。実務でどこまで作業を終えられたかは、利用後の確認票（このテキストの「4 任意の利用確認票」）で整理できます。記入や提出は任意です。続きと翌月の作業は保存した記録と翌月の始め方（このテキストの「2 同じ月の続きと翌月利用」）へ進んでください。

開発者は星野宇潮（https://invaders.co.jp/members/hoshino-ushio.html）です。判定の候補を作り、利用者が元資料を確認して判断と理由を残す構成です。使い分けと「手続・記録・署名」の説明（GUIDE.md）も確認できます。


2 同じ月の続きと翌月利用
========================

保存した記録を再開し、前月を残して翌月を始める

同じ月の続きを行う場合は保存したJSONを開きます。翌月を始める場合は、新しい対象月と帳簿・請求の両方を用意し直します。前月の判断は翌月の取引へ自動で引き継ぎません。

同じ月の続きを行う

monthly-reconcile.htmlを開き、「保存した記録を再開する」を開きます。中の「再開するJSON」から前回保存したJSONを選んでください。対象月、帳簿・請求の入力名、記入と未記入・未解決の行数を確認します。読み込み後も、未解決の行が解決したことにはなりません。

確認者IDを入力し、必要な行を確認して判断と理由を記録します。作業後はJSONとCSVを両方保存します。前回のファイルと区別できるよう、保存後に対象月と保存日を付けて管理できます。例は「2026-09_照合記録_20261013.json」「2026-09_確認表_20261013.csv」です。これらはファイル名の例で、画面が自動で付ける名前ではありません。拡張子の.jsonと.csvを保ってください。

JSONの中身や元のCSVをこの案内に合わせて書き換える必要はありません。前回の記録を残し、新しく保存した記録を別のタブで開いて確かめてから、元の画面を閉じます。

前月の記録を残して翌月を始める

1. 前月のJSONとCSVを保存し、ダウンロード先に両方あることを確認します。
2. 同じHTMLを別のタブで開きます。この方法なら前月の画面も残せます。
3. 対象月を翌月へ変更し、帳簿と請求の両側に、その月のCSVを入れます。入力名もその月の資料にそろえます。
4. 「候補を作成する」を押し、新しい対象月・入力行数・候補数を確認します。新しい入力の判断は未記入から始まります。
5. 元資料を見て判断と理由を記録し、翌月用のJSONとCSVを保存します。

同じタブで切り替える場合は、先に前月の2ファイルを保存します。「保存して入力を変更する」を押し、確認欄の「保存済み 入力変更へ進む」へ進んでください。画面の判断記録が解除されます。対象月だけを変更せず、帳簿・請求の両方と入力名も翌月の資料へ差し替えます。このボタンが保存済みかを自動検査するわけではないため、保存先の確認が必要です。

前月の未解決を翌月の通常取引として取り込まず、前月の確認表に残して原資料を確認してください。前月の続きを行うときは、前月のJSONを別のタブで開きます。

よくあるつまずき

| 状況 | 確認すること |
|---|---|
| 前の判断が表示されない | 元のCSVではなく、保存した再開用JSONを選んだか確認します |
| 再開後の確認者IDが空欄 | 記録は保持されます。行を開くときや新しい判断を追加するときにIDを入力します |
| 翌月の取引が対象月外になる | 対象月とCSVの日付がそろっているか確認します |
| 翌月に前月の取引が残る | 帳簿・請求の両側と入力名を差し替えたか確認します |
| 保存できたが未解決が残る | 未解決も保存できます。資料を確認し、全件完了として扱いません |

月次照合で行うのは、資料の比較と判断の記録です。月次決算や税務申告全体が完了した意味ではありません。翌月にも使えたか、どの作業が残ったかは利用後の確認票（このテキストの「4 任意の利用確認票」）で整理できます。


3 CSVの準備
========================

帳簿と請求のCSVを、照合できる3列にそろえる

月次照合に入れるのは、同じ対象月・同じ金額の基準で比較する帳簿と請求一覧です。会計ソフトの仕訳帳CSV全体を、そのまま比較する形式ではありません。先に架空の3列入力例（fixtures/preparation-ledger.csv）で列の形を確認してください。

まず2つの架空例を読み込む

同梱のfixtures/preparation-ledger.csvとfixtures/preparation-invoices.csvは、どちらも2行の架空データです。monthly-reconcile.htmlを別の新しいタブで開き、対象月を2026年9月にして、帳簿と請求の各欄でCSVを選びます。「候補を作成する」を押すと入力4行、照合候補1組になります。もう一つの取引は金額が違うため、確認が必要な行に残ります。確認者IDへA01などを入力してから、候補を開いてください。

実在する会社や取引の例ではありません。この4行を実務の正解や時短実績として使わないでください。このまま確認する場合は、START.md（このテキストの「1 初回の確認と保存・再開」）の「判断と理由を記録する」「2つのファイルを保存し、別のタブで再開する」の操作を使えます。最初の「架空データで試す」は押し直しません。1組を採用した後は記入2行・未記入未解決2行で、再開後も同じ行数を確認します。STARTにある200行・198行は、別の同梱デモの件数です。

自分の資料から、比較する行を決める

元のCSVを保持し、作業用のコピーを作ります。対象月と比較したい明細を両側でそろえ、請求額と比較する帳簿明細を選びます。どの明細を対象にすべきか不明な場合は、担当者へ確認します。仕訳の借方と貸方を両方取り込んだり、入金額と請求額を同じ意味の金額として扱ったりしないでください。

3列の簡易入力は、列名も順序も次の形にそろえます。

日付,相手先,金額
2026-09-01,架空比較A,10000

| 入力列 | 確認する内容 |
|---|---|
| 日付 | 比較する明細の日付。YYYY-MM-DDで記入し、両側で同じ意味の日付を使います |
| 相手先 | 元資料で確認できる同じ取引先。似た名称だけで同じ会社と決めません |
| 金額 | 両側で税込の請求額にそろえた正の整数円。通貨記号や桁区切りのカンマを付けません |

表計算ソフトを使う場合は、作業用の表に3列を作り、対象明細の値を移します。元の値を消したり、金額を推測して補ったりしません。日付の表示はYYYY-MM-DD、CSVの文字コードはUTF-8、区切りはカンマにします。保存したCSVを文字として開き、先頭行と実際の値を確認してください。見た目の日付の表示だけを変えても、CSVの出力が同じ形式とは限りません。

税抜金額を税込金額と比較する場合、日付や金額が確定しない場合、返金・分割・合算がある場合は、自動で一つの通常明細へ変換しません。原資料で基準を確認し、必要な確認事項を残してください。元のファイル名・行番号を入力内にも残したい場合は、READMEの標準6列（README.md#自分のcsvを使う）を使えます。

1ファイル300行・1MBまでです。上限に合わせて黙って行を落とさず、対象を分ける場合は範囲と条件を記録します。読み込んだ後も対象月・入力行数・元資料の行を確認してください。

freeeの出力設定を利用する場合

freeeの公式案内には、CSVテンプレートで出力項目を選び、列名と順序を変更する方法があります。利用可能なプランは公式案内で確認してください。UTF-8で出力できる設定もあります。freee公式のCSV出力案内（https://support.freee.co.jp/hc/ja/articles/204615564）

この設定を使う場合も、必要な明細・日付・取引先・税込金額を正しく選べるかを確認してから、3列の受入条件に合わせます。列名を変えただけで、借方・貸方・税抜・税込の違いが解消するわけではありません。

今回確認したのは公式の機能説明と、同梱の架空CSVが月次照合で読めることです。freeeのアカウント画面から実際に書き出したCSVの互換性を確認した成果ではありません。専用の自動変換機能は追加していません。

マネーフォワードのCSVを利用する場合

マネーフォワードの仕訳帳では、CSV形式とMF形式で出力される項目が異なります。公式案内のCSV列には、取引日・取引先・金額などに加えて複数の項目があります。マネーフォワード公式の仕訳帳案内（https://biz.moneyforward.com/support/account/guide/books2/bo01.html）

月次照合の3列または6列へそろえる準備が必要です。取引日・取引先・金額という名前だけから、一律に正しい対応だとは決めません。元資料の比較対象と金額の基準を確認し、作業用のコピーで必要な行と列を用意してください。マネーフォワードの実出力を読み込んだ検証は今回行っていません。

保存と利用成果の確認へ進む

候補を作成した後は、人が両側の元資料を見て判断と理由を記録し、JSONとCSVを保存します。未解決の行も残ります。CSVの準備が難しかった点は任意の利用確認票（このテキストの「4 任意の利用確認票」）へ書けます。完了した作業を事例として整理する場合は事例記録のひな形（このテキストの「5 事例記録のひな形」）を使ってください。

開発者は星野宇潮（https://invaders.co.jp/members/hoshino-ushio.html）です。元資料の確認と記録を残す考え方は使い分けガイド（GUIDE.md）にあります。


4 任意の利用確認票
========================

利用後に、終えた作業と残った作業を整理する

月次照合を使った後、自分で完了した作業と、確認が残る作業を振り返るための任意の確認票です。時間、保存ファイル、氏名・連絡先の提出は必須ではありません。実在する会社名や取引先名、金額、業務資料は記入しないでください。

この文書には送信機能や自動収集機能はありません。自分の端末へコピーして記入できます。記入した票や実データを、公開GitHubのIssueやリポジトリへアップロードしないでください。

初回の利用後に記入する

| 項目 | 記入欄 |
|---|---|
| 利用した製品と版 |  |
| 入力の種類 | 架空データ／自社の資料／その他／不明 |
| 今回、自分で終えられた作業 |  |
| 終わらずに残った作業と、その理由 |  |
| 従来、この作業を行っていた人 | 自分／社内の担当者／会計士・税理士など／その他／不明 |
| 説明・操作の代行・結果の再確認を受けたか | 受けていない／受けた／不明 |
| 支援を受けた箇所 | 氏名を書かず、必要だった支援だけ記入 |
| 次の月も使いたいか | 使いたい／使いたくない／まだ決めていない |

次の月に実際に使った後に追記する

| 項目 | 記入欄 |
|---|---|
| 次の月にも使ったか | 使った／使っていない／対象の作業がなかった |
| 記録の再開と新しい月への切り替えで困ったこと |  |
| 次の月に終えられた作業と残った作業 |  |
| 次の月に必要だった支援 |  |

「使いたい」という回答と、実際に翌月使ったことは区別します。架空データの操作確認と、自社資料での実務利用も分けてください。従来自分で行っていた作業の負担軽減を、専門家へ依頼していた作業の代替として扱いません。

記入しただけで、公表への同意にはなりません。事例として掲載する場合は、掲載する内容と場所を別に確認します。提出や掲載をしなくても、製品の利用は続けられます。


5 事例記録のひな形
========================

自分で終えた作業を、根拠と残った確認に分けて記録する

月次照合の利用成果を整理するためのひな形です。時間の実測や保存ファイルの提出は必須ではありません。未回答の項目は「不明」として残せます。架空例の操作確認と、自社資料を使った実務の成果は別々に記録してください。

記録する項目

| 項目 | 記入欄 |
|---|---|
| 利用した製品・配布版 |  |
| 記録の種類 | 架空データの操作確認／実務の本人報告／資料で確認した実務成果／不明 |
| 対象にした作業 |  |
| 従来その作業を行っていた人 | 自分／社内担当者／会計士・税理士など／その他／不明 |
| 自分で終えられた作業 |  |
| 残った作業・未解決とその理由 |  |
| 説明・代行・再確認など、必要だった支援 |  |
| 結果を確認した方法 | 本人の回答／端末上での確認／資料の確認／不明 |
| 翌月にも実際に利用したか | 利用した／利用していない／対象の作業がなかった／不明 |
| 記入者以外が同じ手順を試したか | 試した／試していない／不明 |

氏名・連絡先・会社名・取引先名・実際の金額をこのひな形へ入れる必要はありません。記入した票や実務の保存ファイルを、公開GitHubへアップロードしないでください。記入しただけで公表への同意にはなりません。

紹介する文章を作るとき

まず対象作業を示し、利用者が行った操作、自分で完了した部分、残った確認、必要だった支援を順に説明します。「自分で行っていた作業が楽になった」と「専門家へ依頼していた作業を自分で終えた」は区別します。照合を終えたことを、月次決算・申告・監査全体の完了へ広げません。

時間の報告を紹介する場合は、誰の報告かと対象作業を示します。比較元や対象範囲が不明なら、その部分を推測で埋めません。希望として「次も使いたい」と答えたことを、翌月の実利用には数えません。

公表する場合は、利用者に掲載する本文・場所と匿名化の範囲を確認します。回答を取得していない項目は、AIや担当者が体験談として作りません。公表せず、利用者自身の振り返りに使うこともできます。

再現手順と作者へつなぐ

事例を読む人が同じ操作を試せるよう、架空データの初回確認と保存・再開（このテキストの「1 初回の確認と保存・再開」）、CSVの準備（このテキストの「3 CSVの準備」）、翌月の始め方（このテキストの「2 同じ月の続きと翌月利用」）を案内できます。架空の再現例を、事例の実取引データとして説明しないでください。

月次照合の開発者は星野宇潮（https://invaders.co.jp/members/hoshino-ushio.html）です。元資料を比べる手続、判断と理由の記録、担当者が結論を引き受ける役割は、使い分けガイド（GUIDE.md）で説明しています。
